# 词汇板块设计规范 v1

> 适用范围:`/vocab` 词库中心、词库详情、词卡、复习/错题关、统计视图。
> 本文是**前端与后续 edge function 的共用规格** —— 掌握判定和错题判定两边必须
> 算出同一个结果,任何一边改了,另一边同步改,以本文为准。
>
> 状态:v1,随第一个托福 200 词试跑批次定稿。未落地的部分标了「待实现」。

---

## 0. 一句话审美目标

**克制**。整屏只有一处渐变、一处大字号数字、四处动效。其余全是白卡 + 细边 + 大留白。
学习类产品最怕"每个元素都在喊",信息层级一旦拉平,用户就不知道该看哪。

---

## 1. 渐变的唯一位置

**一屏只允许出现一处渐变,且只能是主 CTA。**

- 主 CTA(「开始学习」/「继续复习」/「邮箱注册」)= 品牌橙渐变
- 其余所有容器 = 白底 + `1px` 细边(`hsl(0 0% 0% / 0.08)`)+ 圆角 `16px`
- 次级按钮 = 白底 + 细边 + 深色文字,**不许**用浅色渐变"降级模仿"主 CTA

```css
/* ⚠️ 新增 token,不要动 --grad-brand。
   全站现有品牌渐变是 紫→品红→珊瑚(src/index.css:76),
   词汇板块的橙是这个板块专属的,覆盖 --grad-brand 会波及全站。 */
--grad-vocab-cta: linear-gradient(135deg, #F5A524 0%, #EF7C1B 55%, #E2600F 100%);
--vocab-cta-shadow: 0 6px 20px hsl(24 90% 45% / 0.25);
```

判定标准:截一张图,把渐变区域涂黑,如果涂黑面积超过一块,就是违规。

> ⚠️ Tailwind 透明度必须是 5 的倍数(`/85`、`/90` 可以,`/88` 会直接渲染成全透明)。
> 这是本仓库踩过的坑,写任意 `bg-[#xxx]/NN` 前先确认 NN % 5 === 0。

## 2. 字体系统

| 用途 | 字体栈 | 字号 | 字重 |
| --- | --- | --- | --- |
| 统计数字 | `Manrope, "DIN Alternate", "DIN Condensed", ui-sans-serif, system-ui` | 40–56px | 700 |
| 词头 headword | `"Source Serif 4", "Source Serif Pro", Georgia, "Songti SC", serif` | 48px | 600 |
| 例句 | 正文无衬线栈 | 17px | 400 |
| 中文释义 | 正文无衬线栈 | 15px | 500 |
| 标签 / 元信息 | 正文无衬线栈 | 12px | 500,字间距 `0.02em` |

- 统计数字必须**等宽**(`font-variant-numeric: tabular-nums`),否则 count-up 动画过程中
  数字宽度跳变,整行会左右抖。这是最容易被忽略的一条。
- 词头用衬线体是刻意的:它是全屏唯一的衬线元素,天然成为视觉锚点,不需要再加颜色或底色去强调。

## 4. 词卡版式

```
┌──────────────────────────────────┐
│                                   │
│            abandon                │  ← 衬线 48px,水平居中
│           /əˈbændən/              │  ← 12px,灰,居中,可点朗读
│                                   │
│  放弃;抛弃                        │  ← 15px 中文释义
│  to leave someone permanently      │  ← 13px 灰 英文释义
│                                   │
│  ──────────────────────────────   │  ← 1px 细分割线
│  abandon a plan                   │  ← 12px 搭配标签
│  The city abandoned its plan to…  │  ← 17px 例句
│  该市放弃了拓宽这条繁忙道路的计划。 │  ← 14px 灰 译文
│  ──────────────────────────────   │
│  abandon a child                  │
│  …                                │
└──────────────────────────────────┘
```

- 例句区**每条之间一条 `1px` 细分割线**,不用卡片嵌卡片,不用底色分区。
- 三条例句按 `sort_order` 升序 = 搭配频率降序,**第一条永远是最高频用法**,不要按字母或随机排。
- 音标和例句都可点朗读;朗读中的那一条左侧显示一个 `2px` 竖条,不换底色。

## 5. 动效白名单

**只有这四处允许有动效,其余一律无过渡。**

| # | 位置 | 规格 |
| --- | --- | --- |
| 1 | 统计环扫出 | `600ms`,`cubic-bezier(0.22, 1, 0.36, 1)`,首次进入视口时触发一次 |
| 2 | 统计数字 count-up | `800ms`,从 0 到目标值,`tabular-nums` 防抖 |
| 3 | 答对打勾 | 上浮 `8px` + 淡入,`220ms`,随后 `400ms` 淡出 |
| 4 | 里程碑 confetti | 仅在「掌握词数」跨过 50/100/200/500/1000 时触发一次,`1200ms` |

- 上述之外,**hover 不放大、卡片不投影渐变、页面切换不做转场**。
- 全部动效必须尊重 `prefers-reduced-motion: reduce` —— 命中时统计环和 count-up
  直接落终值,打勾只淡入不上浮,confetti 完全不放。

## 6. 顶部统计双视图

- 两个视图:**圆环**(默认)/ **柱状图**,右上角滑钮切换。
- 偏好存 `localStorage`,key = `vocab_stats_view`,值 `"ring" | "bar"`。
- 读取失败或值非法一律回落 `"ring"`。
- 切换本身无动画;切过去之后该视图的入场动效(环扫出 / 柱升起)照常放一次。

三个统计口径(两个视图展示的是同一组数):

| 指标 | 定义 |
| --- | --- |
| 已掌握 | 满足第 7 节「掌握」判定的词数 |
| 学习中 | 有作答记录且 `mastery_level` 在 0–3 |
| 未开始 | 该词库总词数 − 已掌握 − 学习中 |

## 7. 掌握与错题逻辑规格

> **这一节是前端与 edge function 的共用契约。**两边必须算出同一个结果。
> 涉及表:`user_vocab_mastery`、`vocab_mistake_book`。

### 7.1 入表条件

**只有"作答"入表。浏览词卡、点朗读、听音频,都不入表、不改任何计数。**
这一条决定了统计的可信度 —— 翻一遍词卡不能算学过。

### 7.2 答对

条件:`mastery_level` 上限 5。

```
若 last_correct_date <> 今天:          -- 当天首次答对
    mastery_level  = min(mastery_level + 1, 5)
    correct_days   = correct_days + 1
    last_correct_date = 今天
modes_correct = modes_correct ∪ {本次 mode}   -- 去重数组,当天重复答对也记 mode
tested_count  = tested_count + 1
review_interval_idx = min(review_interval_idx + 1, 5)   -- 答对进档
next_review_at = 今天 + REVIEW_INTERVALS[review_interval_idx] 天
```

> 当天第二次答对**不再加** `mastery_level` / `correct_days` —— 否则刷同一个词十遍就"掌握"了。
> 但 `modes_correct` 仍然要并入,因为换了题型答对是有信息量的。

### 7.3 答错

```
mastery_level = max(mastery_level - 2, 0)
tested_count  = tested_count + 1
review_interval_idx = 0                      -- 答错回第一档
next_review_at = 今天 + 1 天
→ 同时写入错题本(见 7.6)
```

`-2` 是刻意的:答错的惩罚必须大于答对的奖励(`+1`),否则蒙对蒙错各半的词会缓慢爬到"掌握"。

### 7.4 掌握判定

**三个条件同时成立**才算掌握:

```
mastery_level >= 4
AND correct_days >= 4                        -- 至少 4 个不同自然日答对过
AND array_length(distinct modes_correct) >= 2 -- 至少在 2 种题型下答对过
```

三条各挡一种作弊:等级挡随机蒙对,天数挡一天刷完,题型挡"只会认不会拼"。

### 7.5 学习中判定

```
有作答记录(tested_count > 0)AND mastery_level 在 0–3
```

### 7.6 复习间隔

```
REVIEW_INTERVALS = [1, 2, 4, 7, 15, 30]   // 天,下标即 review_interval_idx
```

- 答对 → `idx + 1`(封顶 5,即 30 天)
- 答错 → `idx = 0`(回到 1 天)

### 7.7 错题本

**入册**:任何一次答错 → 写 `vocab_mistake_book`。

```
INSERT (user_id, word_id, headword_snapshot, last_wrong_mode, status='active')
ON CONFLICT (user_id, word_id) DO UPDATE
  SET wrong_total     = wrong_total + 1,
      last_wrong_mode = 本次 mode,
      status          = 'active',        -- 已移出的词再错要重新入册
      streak_days     = 0,               -- ⚠️ 关键:错一次,连对进度清零
      cleared_at      = NULL
```

**移出**:`streak_days` 达到 **3** 时移出(`status='cleared'`,`cleared_at=now()`)。

`streak_days` 的精确定义 —— 这三条缺一不可:

1. **不同自然日**:同一天连对 3 次只算 1 天(靠 `last_streak_date <> 今天` 判断)
2. **中间无错**:期间任何一次答错立即清零
3. **全站任何答对都算**:不限于在错题关里答对 —— 在词库正常学习中答对同样累加

```
答对时:
  若 last_streak_date <> 今天:
      streak_days = streak_days + 1
      last_streak_date = 今天
      若 streak_days >= 3: status = 'cleared', cleared_at = now()
```

### 7.8 错题关卡规则

- 每轮 **10 词**,需答对 **6** 词(60%)通过。
- 不足 10 词时按同比例向上取整:`需对 = ceil(实际词数 × 0.6)`。
- 累计正确率 `< 60%` → 自动续下一轮。
- **3 轮仍不达标 → 允许关闭**,提示文案固定为:

  > 今天状态不佳,明天再战

  这条是产品态度:不把用户困在失败循环里。第 3 轮结束后关闭按钮必须真的可点。

### 7.9 反馈弹层

- 每次作答后弹出,展示**例句 1**(`sort_order = 1`,即最高频搭配那句)并**自动朗读**。
- 设置项 `vocab_autoplay_feedback`(默认开)可关闭自动朗读;关掉后弹层照常显示,只是不出声。

## 8. 词库中心页

- 卡片列表**从 `vocab_banks` 动态渲染**,不在前端硬编码 11 个词库。
  排序按 `sort_order` 升序。
- `is_active = true` → 正常卡片,可进入。
- `is_active = false` → 进页面底部的**「敬请期待」占位区**:灰度身份色、无点击态、
  不显示词数进度,只显示名称。
- 占位区整体加一个区块标题「敬请期待」,不要把可用和不可用的卡混在一个网格里 ——
  混排会让用户反复点到不可用的卡。

> 当前实际状态:11 个库中只有 `toefl` 是 `is_active = true`,其余 10 个全在占位区。

## 9. 未注册用户测试闸门

### 9.1 配额

- 未登录用户的**作答**次数存 `localStorage`,key = `vocab_guest_answers`。
- 上限 **20** 次。第 **21** 次作答**之前**弹注册墙(即用户能完整做完 20 题)。
- 与第 7.1 节一致:只有作答计数,浏览词卡/听音不计。

### 9.2 注册墙弹层

- **不可点击遮罩关闭,无 X 按钮**。这是硬闸门,不是可跳过的提示。
- 主标题:**注册后继续,进度不丢失**
- 副文案显示 guest 期战绩,实际数字来自本地记录:

  > 已测 {X} 词 · 答对 {Y} 个

- 主按钮「**邮箱注册**」= 全屏唯一渐变位(见第 1 节)
- 次入口「已有账号,登录」= 纯文字链,无边框无底色

#### 邮箱输入:后缀一键补全

用户在邮箱框输入 `@` 之前或刚输入 `@` 时,下方浮出常用后缀候选,点一下补全:

```
qq.com · 163.com · 126.com · gmail.com · outlook.com
```

- 触发时机:输入框内容非空且**不含 `@`**,或已输入 `@` 但 `@` 之后为空/为候选前缀。
- 候选按上面顺序排,`qq.com` 和 `163.com` 排前两位(国内用户占比最高)。
- 点击候选 = 把 `<已输入部分>@<后缀>` 写回输入框并关闭候选,焦点留在输入框。
- 候选是**辅助不是限制**:用户手打任何其他域名都正常接受,不做域名白名单校验。
- 候选条无渐变、无阴影,白底细边,与第 1 节的"唯一渐变位"规则不冲突。

#### 微信登录:预留位

- 在「已有账号,登录」之上预留一个**微信登录**按钮位。
- 由 feature flag 控制,**默认关闭**(`VITE_VOCAB_WECHAT_LOGIN`,默认 `false`)。
- 关闭时**整个按钮不渲染**,不要渲染成灰色禁用态 —— 灰色禁用态会让用户反复点。
- 打开后按钮样式:白底 + 细边 + 微信绿图标,**不占渐变位**(渐变永远只属于「邮箱注册」)。
- 本轮只留位,不接微信 OAuth。真接的时候单独立项。

### 9.3 进度迁移 —— 必须做

guest 期的每次作答同存 `localStorage`,key = `vocab_guest_records`,每条:

```jsonc
{ "word_id": "uuid", "correct": true, "mode": "quiz", "date": "2026-08-03" }
```

**注册或登录成功后,一次性把这些记录按第 7 节的判定逻辑"重放"进
`user_vocab_mastery` 和 `vocab_mistake_book`,然后清空 localStorage。**

重放要求:

- 按 `date` 升序重放,保证"当天首次答对"和 `streak_days` 的自然日判定算得对 ——
  乱序重放会把多天的进度压成一天,`correct_days` 就错了。
- 重放走的必须是**同一套判定逻辑**(第 7 节),不是另写一份简化版。
- 迁移成功后才清 `localStorage`;迁移失败保留数据并可重试,不能一边失败一边清空。
- 迁移是幂等的:重复迁移同一批记录不应让计数翻倍(以 `word_id + date + mode` 去重)。

> ⚠️ **这条不是可选项。** 文案承诺了"进度不丢失",不做迁移就是假承诺。
> 要么做迁移,要么改文案 —— 不允许留着文案不做迁移。

### 9.4 已知局限(接受)

- `localStorage` 可被清除/无痕模式绕过 → **接受**,不做指纹追踪。
  被清除即**视为重新体验**,重新给 20 次配额,不做任何找回或惩罚。
- 服务端只保证一件事:**未登录状态调不到任何写库接口** —— RLS 已天然保证
  (`user_vocab_mastery` / `vocab_mistake_book` 的策略都绑 `auth.uid()`)。
  也就是说绕过闸门最多能多做几道题,拿不到任何服务端写入。

## 10. 内容侧的既定事实(影响前端)

这几条来自内容生成流水线(`scripts/vocab/`),前端按此假设即可:

- 每个词**恰好 3 条例句**,`sort_order` 为 1/2/3,1 = 最高频搭配。
- 例句长度 **8–16 词**,不会出现超长句撑破卡片。
- 全站例句**不含 em-dash / en-dash**,排版不必处理破折号换行。
- `def_en` **不超过 15 词**,单行到两行可容纳。
- 例句的 `scene`(academic / news / daily_life 等 10 类)**只存在于生成期**,
  `vocab_examples` 表**没有 scene 列**,前端拿不到,别按场景做筛选 UI。
  要做得先加列 + 回填。
- 词音频与例句音频都走内容寻址 CDN(`<hash 前两位>/<hash>.mp3`),
  **没有 `vocab/` 前缀** —— tts edge 是全站共用的内容寻址存储,
  同一句话在哪个板块都是同一个文件。
