## 以后再遇到损坏对象，按这个流程

### 第 1 步：删除对象（两条路，任选）

**A. Dashboard UI（最省事，不碰密钥）**
Supabase → Storage → 桶 `tts-audio` → 进 `<hash 前两位>/` 目录 → 搜 hash 前几位 → 删除该文件。

**B. Storage API（可脚本化）**
`service_role` key 在 Dashboard → Project Settings → API。**不要**把它贴进仓库或聊天里。

```bash
SRK='<粘贴 service_role key>'
BUCKET=tts-audio
OBJ='b1/b13ea61fcc29dc2ddf1a18c8050a85c0287bf6a2009f9978a51b35a5eb8b6ff2.mp3'

curl -i -X DELETE \
  "https://degqpiiddkxcuzwombwp.supabase.co/storage/v1/object/$BUCKET/$OBJ" \
  -H "Authorization: Bearer $SRK" -H "apikey: $SRK"
# 期望 200 + {"message":"Successfully deleted"}
```

> ❌ 不要再写 `DELETE FROM storage.objects …`：被 `storage.protect_delete()` 拦，报 42501。

### 第 2 步：清 CDN 缓存（**不能省**）

上传时带的是 `Cache-Control: public, max-age=31536000, immutable`，所以 Cloudflare 会继续吐旧副本。
在 Cloudflare 控制台对该对象的 CDN URL 做一次 Purge：

```
https://audio.bigmooneducation.com/<hash 前两位>/<完整 hash>.mp3
```

### 第 3 步：预热 + 复验（CC 侧可做，anon key 足够）

顺序不可换；任一步不过就停下报告，**不要重试掩盖**：

1. `HEAD` 确认对象已消失（或至少已不是原来那个坏体积）。**仍是坏体积 = purge 未生效**，此时预热会拿回旧副本、得到假绿 → 停。
2. 调一次 tts edge 触发合成（参数必须与线上播放一致：`voiceId` + `speed` 取自该内容源的可达档位矩阵）。
3. `HEAD` 复验：**200 且 ≥ 2KB**。
4. 下载并**逐帧解析 MPEG 帧头**，确认帧数/时长在同类正常范围（单词约 0.6–2.5s）。
   **只看字节数不算通过**——1920 字节那次就是"体积看着小但仍是合法 mp3"。

npm run audio:audit     # 期望：前置三条全过 + 缺失 0
